# QQ 文件转发与弹窗触摸路由

2026-11-11 用户确认收到的文件能够显示“已下载”，随后反馈可以选择联系人，
但确认转发后目标聊天没有文件；继续操作时又反馈点击后没有联系人弹窗。
这是接收文件页启动故障之后的后续问题，不能直接套用照片返回聊天补丁。

## 已确认的宿主缺口

运行日志显示 QQ 使用 `SharePanelDialogFragment` 分享面板，因此没有新的
`ForwardRecentActivity` 启动记录并不等于没有选择联系人。后续操作记录中
还出现多个 `PopupWindow`；运行时诊断显示 QQ 主线程仍在正常消息队列中
等待，未发现新的未捕获异常。临时原生日志抓取已经安全脱离，未抓到可
确认发送成败的转发返回码；不能把这段抓取当作转发接口未执行的证明。

部署的 `SdWindowSession.deliver()` 把第一次按下交给 `top()`。`top()` 用于
键盘焦点，跳过所有 `FLAG_NOT_FOCUSABLE` 窗口。Android 的“不抢键盘焦点”
与“不能点击”是不同属性：可见、可触摸的非聚焦弹窗因此收不到点击，而
后面的聊天 Activity 收到本应落在弹窗上的触摸。这是源码及部署 DEX 中
均存在的、可由受控窗口测试重现的输入路由错误。

它能解释此类弹窗点不动，但尚未证明此前确认转发后没有文件的全部原因。
联系人选择或弹窗正常显示，均不能单独证明 QQ 后端转发成功。

## 修复范围

`scripts/api29/popup-touch-target-compat/` 只修复触摸目标选择：

- 使用既有绘制层次，从最上层向下选择可见、可触摸且有输入通道的窗口。
- 非聚焦弹窗内的点击交给弹窗；弹窗外的点击可透传给下层。
- 保留聚焦模态窗口接收外部点击的规则；不改变键盘焦点选择。
- 只在手势第一次按下时选择目标，保留后续多指、移动、抬起、取消与原有
  窗口局部坐标转换。
- 安全标记 `SDINPUT=nonfocusable_touch_target` 只记录选中了此类窗口，
  不记录文件、消息或联系人内容。

自定义触摸 inset/region、`ACTION_OUTSIDE` 监听和 split-touch 等完整
Android 输入语义不在这次新增范围内。没有更改 QQ APK、替换 QQ 转发实现、
伪造发送成功或代用户发送文件。既有登录、文件选择器、照片返回聊天及
ManifestReceiver 修复保留。
